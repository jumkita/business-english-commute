## 1. 目的と背景

### 1.1 目的

移動時間（徒歩・電車・待ち時間）のスキマ時間を使って、**ビジネスの現場で英語が使えるようになる**ための基礎力を包括的に鍛える。

### 1.2 「使える」の定義（ゴール）

| 観点 | 到達目標 |
|------|----------|
| 語彙 | ビジネス頻出語・コロケーションを「見て分かる」だけでなく「聞いて即分かる」 |
| リスニング | ネイティブの自然な速度で起きる音変化（リエゾン等）を聞き取り、一語ずつ正確に書き取れる |
| スピーキング | 会議・交渉・メールで使う定型表現を、丁寧さのレベルを選んで口に出せる |
| 継続 | 1日合計 15〜30 分を、移動時間だけで無理なく続けられる |

### 1.3 想定ユーザー

- 利用者: 本人のみ（1名）
- レベル: 中上級（TOEIC 750 以上）。基礎文法は理解済みで、**「知っている」を「使える」に変える**段階
- 利用端末: iPhone の Safari（ホーム画面に追加して使う場合を含む）。Android と PC は動作保証の対象外
- 通信: オンライン前提（移動中もモバイル回線につながっている）
- 利用場面: 主に片手操作。満員電車ではイヤホンで音声のみ、座れる時や待ち時間は画面を操作

## 2. スコープ

### 2.1 対象とする学習領域

| No | 領域 | 内容 | 中上級向けの重点 |
|----|------|------|------------------|
| A | ボキャブラリー | ビジネス頻出の単語・句動詞・コロケーション | 言い換え（get → obtain）、ニュアンス差、コロケーション |
| B | 音声変化（リエゾン等） | 連結・脱落・同化・弾音化・弱形・縮約・文強勢とイントネーション・チャンク（意味のまとまり） | ルールの理解と、自然な速度での聞き取り・再現 |
| C | ビジネス表現 | 会議・プレゼン・交渉・メール/チャット・オンライン会議・雑談・フィードバックの場面別フレーズ | 丁寧さのレベル、婉曲表現（would / might / I was wondering if...） |
| D | 実務文法 | 助動詞・仮定法・時制による丁寧さの調整、冠詞、前置詞 | 「どちらがより自然か・丁寧か」を選ぶ問題 |
| E | リスニング | 短いビジネス会話（30〜60 秒） | 速度を変えた反復とディクテーション |

### 2.2 対象外（今回はやらない）

- 複数ユーザー対応、ログイン、課金
- AI による学習コンテンツの自動生成（コンテンツは同梱データで用意する）
- ネイティブアプリ化、ストア公開
- オフライン動作（オンライン前提とする）
- 有料の音声認識サービス（音声認識は無料で使える方式に限る）
- 聞き流しでの日本語音声（音声は英語のみ）
- TOEIC 等の模試機能

## 3. システム構成方針

既存の `stock-daytrade` と同じ形式に揃える。

| 項目 | 方針 |
|------|------|
| 言語 / UI | Python 3.11 + Streamlit |
| 公開 | GitHub の公開リポジトリ（`jumkita/` 配下）から Streamlit Community Cloud にデプロイ |
| 秘密情報 | Streamlit Secrets で管理（リポジトリには `.env.example` と Secrets 例のみ置く） |
| テスト | pytest + GitHub Actions（`push` / `pull_request` で自動実行） |
| 学習コンテンツ | `data/content/*.json` としてリポジトリに同梱 |
| 音声 | （v0.4）当面は iPhone 内蔵の読み上げ（Web Speech API の `speechSynthesis`、米国英語の声）で再生する<br>（非推奨・v0.3 までの方針）事前生成した MP3 を同梱（生成スクリプトを `scripts/` に置く）。Q-03 の結論が出たら再検討する |
| 学習履歴 | 非公開の GitHub Gist に JSON で保存（Gist 用トークンは Secrets に保存。HTTP 通信は標準ライブラリで行い、依存を増やさない） |
| 発音判定 | iPhone の Safari 標準の音声認識（Web Speech API、無料）を、自作の Streamlit コンポーネント（HTML/JS のみ、npm ビルドなし）から呼ぶ |
| 英文の照合 | ディクテーション・発音・シャドーイングで共通の照合処理（`english_app/text_match.py`）を使う |

### 3.1 想定ディレクトリ構成

（非推奨・v0.3 時点の案）実装後の構成は README の「構成」を参照。主な違いは、コンテンツの読み込みが `content.py`、照合以外の出題が `quiz.py`・`dictation.py`・`listening.py` に分かれたこと、`audio.py`・`data/audio/`・`scripts/generate_audio.py` がまだないこと。

```
business-english-commute/
```

## 4. 機能要件

優先度は **Must**（初期版に必須）/ **Should**（第2段階）/ **Could**（余力があれば）とする。

### 4.1 学習モード

#### FR-01 タップ式クイズ（Must）

座れる電車内や待ち時間向けに、**画面を見て親指だけで答えられる**クイズ。

- セッションの長さを「3分 / 5分 / 10分」から選べる（問題数ではなく時間で区切る）
- 出題形式
  - 英→日の意味選択（4択）
  - 日→英の表現選択（4択）
  - 音声を聞いて意味を選ぶ（4択）
  - 音声変化の聞き取り：音声を聞いて、実際に言われた文を選ぶ
  - 丁寧さ・自然さの比較：2つの表現から適切な方を選ぶ
- 回答直後に正誤・解説・例文音声を表示する
- 対象領域（A〜E）を指定でき、「おまかせ」では復習期限の来た問題を優先して出す

#### FR-02 聞き流しモード（Must：単体再生 / Should：連続再生）

満員電車や徒歩中に**画面を見ずに**学習するモード。

- 音声は英語のみとし、日本語訳は流さない
- 単元ごとに、次の順で音声を連続再生する
  - 英語 → ポーズ（頭の中で繰り返す時間）→ 英語（もう一度）→ 次の項目
- 繰り返し回数（1〜3 回）とポーズの長さ（短い / 普通 / 長い）を選べる
- **画面ロック中も再生が続く**こと（1本に結合した MP3 を再生する方式で実現する想定）
  - v0.4 時点では未達。端末の読み上げは画面ロックで止まるため、「再生中は画面を消さない」スイッチ（Screen Wake Lock API）で代用している。Q-03 で再検討する
- 画面を見たときは、今流れている英文を確認できる（訳は表示しない。必要なら辞書タブで見る）
- 再生速度を 0.8 / 1.0 / 1.2 倍から選べる（Should）
- 「今日の復習対象」から自動でプレイリストを作る（Should）

#### FR-03 発音（Should）

言い回しを覚え、発音を磨くためのモード。v0.4 までの「発音・シャドーイング」から、聞き取りの確認を FR-11 に分けた（v0.5）。

- 英文と日本語の意味、解説（言い回しの使い方・音のつながり）を見ながら、お手本の音声を聞く
- ボタンを押して英文を読み上げる
- Safari 標準の音声認識（無料）で文字起こしし、お手本の文と比べた一致度と、認識されなかった単語を表示する
- 照合は FR-10 と同じ処理（`english_app/text_match.py`）で行う
- 音声認識が使えない場合は、お手本と自分の録音を聞き比べる自己評価モードに切り替える（Streamlit の音声入力機能を使う）

#### FR-10 ディクテーション（Must）

聞いた英語をタイプして、正しく聞き取れたかを確認するモード。座れる電車内や待ち時間向け。

- 英文の音声を聞き、画面の入力欄に聞こえたとおりに英文をタイプして「答え合わせ」を押す
- 音声は何度でも聞き直せる。ゆっくりの音声（0.8 倍程度）でも聞ける（Should）
- 答え合わせでは、正解文と入力文を単語単位で比べ、次を色分けして表示する
  - 正しく書けた単語
  - 抜けた単語
  - 間違えた単語（入力した語と正解の語を並べて表示）
- 次の違いは誤りとして扱わない
  - 大文字と小文字、句読点、余分な空白
  - 縮約形と元の形（I'm / I am、don't / do not など）
  - 数字の書き方（10 / ten、10% / ten percent など。設計で範囲を決める）
- 1 文字違いなどのつづりの小さな誤りは、誤りではなく「惜しい」と表示する（iPhone の自動修正による誤変換を想定）
- 判定は「正解 / 惜しい / 不正解」の 3 段階とし、FR-04 の復習スケジュールに反映する
- 間違えた箇所が音声変化（リエゾン等）によるものなら、該当する規則の解説へのリンクを表示する（Should）
- ヒントとして単語数と各単語の頭文字を表示できる（Should）
- 出題対象は、音声変化（B）の例文を中心に、ビジネス表現（C）とリスニング（E）の会話を 1 文ずつに分けたもの

#### FR-11 シャドーイング（Should）

英語の音声だけを聞いて聞こえたとおりに言い、正しく聞き取れているかを確かめるモード（v0.5 で FR-03 から分けた）。

- 日本語の訳と、日本語の出典名（「音声変化：〜」など）は表示しない
- 英文は、話し終えて判定が出るまで表示しない。聞き取れないときは「英文を見る」で答えを表示できる
- 音声は何度でも聞き直せる。ゆっくりの音声でも聞ける
- 音声認識の結果をお手本の文と照合し、FR-10 と同じ「正解 / 惜しい / 不正解」の 3 段階と、単語ごとの色分けを表示する
- 出題対象は FR-10 と同じ
- v0.5 では、判定の結果を学習履歴（FR-04 の復習スケジュール）には記録しない

### 4.2 学習管理

#### FR-04 間隔反復による復習（Must）

- 各問題に「次回の復習日」を持たせ、正誤と自己評価から間隔を伸び縮みさせる
- 自己評価は片手で押せるように 3 段階（もう一度 / 難しい / 簡単）
- アルゴリズムは SM-2 を簡略化したものを採用する（詳細は設計で決める）

#### FR-05 中断と再開（Must）

- 電車の到着などで途中でアプリを閉じても、回答済みの結果は失われない
- 失うのは最大でも直近の数問分までとする（保存の頻度は設計で決める）

#### FR-06 ダッシュボード（Must：基本 / Should：詳細）

- 今日の復習件数、連続学習日数、今日の学習時間
- 領域別（A〜E）の正答率と習得済み件数（Should）
- 苦手な項目の一覧（Should）

### 4.3 コンテンツ

#### FR-07 学習データの形式（Must）

1件ごとに以下を持つ（領域ごとの差分は設計で決める）。

| 項目 | 内容 | 例 |
|------|------|----|
| id | 一意の ID | `vocab-0001` |
| 領域 | A〜E | `vocabulary` |
| 見出し | 単語・表現 | `streamline` |
| 意味（日本語） | | 合理化する、効率化する |
| ニュアンス・解説 | 使い分け、丁寧さ | improve より「無駄を省く」意味が強い |
| コロケーション | よく一緒に使う語 | streamline the process / operations |
| 例文（英・日） | ビジネス場面の例文 | We need to streamline the approval process. |
| 音声ファイル | 見出しと例文の MP3（英語のみ） | `audio/vocab-0001_ex.mp3` |
| タグ | 場面・難易度 | `meeting`, `level:advanced` |

音声変化（B）の項目は、加えて「規則名」「ゆっくり読んだ場合の発音」「自然な速度での聞こえ方（カナまたは発音記号）」を持つ。

#### FR-08 初期コンテンツの件数（Must）

| 領域 | 初期版 | 最終目標 |
|------|--------|----------|
| A ボキャブラリー | 300 | 1,500 |
| B 音声変化 | 規則 8 種 × 例文 10 = 80 | 200 |
| C ビジネス表現 | 7 場面 × 20 = 140 | 500 |
| D 実務文法 | 50 | 150 |
| E リスニング | 10 本 | 50 本 |

- 初期コンテンツは開発側（AI）が作成して同梱し、利用者は JSON に追記して増やせる
- 追加したデータは、テストでスキーマ（必須項目・ID の重複・音声ファイルの有無）を検証する

#### FR-09 音声の事前生成（Must → v0.4 で保留）

v0.4 では端末の読み上げで代用しているため、以下は Q-03 の結論が出るまで保留とする。

- `scripts/generate_audio.py` で、コンテンツ JSON から英語の MP3 を一括生成する（日本語の音声は作らない）
- 音声は米国アクセントの声で統一する
- 生成済みのファイルは生成し直さない（差分だけ生成する）
- 音声合成の方式は設計段階で比較して決める（Q-03）

## 5. 非機能要件

| No | 分類 | 要件 |
|----|------|------|
| NFR-01 | 操作性 | iPhone 縦画面での片手操作を前提にする。主要ボタンは親指の届く画面下側に置き、タップ領域は 44px 以上 |
| NFR-01b | 操作性 | ディクテーションでは、入力欄を表示してもキーボードで「再生」「答え合わせ」ボタンが隠れない配置にする |
| NFR-02 | 操作性 | 起動してから 2 タップ以内で学習を始められる（「続きから」ボタン） |
| NFR-03 | 性能 | 起動済みのアプリでは、回答から次の問題の表示まで 1 秒以内 |
| NFR-04 | 通信量 | 音声 1 ファイルを 50KB 程度に抑える（モノラル・低ビットレート） |
| NFR-05 | セキュリティ | API キーやアクセストークンはリポジトリに含めず、Streamlit Secrets で管理する |
| NFR-06 | セキュリティ | 公開 URL を他人が開いても、本人の学習履歴を読み書きできない。Secrets に設定したパスコードを入力するまで Gist に接続しない（未入力時は保存なしのお試しモードで動く） |
| NFR-07 | 保守性 | ロジックは `english_app/` に分け、UI なしで pytest できる構造にする |
| NFR-08 | 品質 | 間隔反復・採点・英文の照合（ディクテーション）・コンテンツ検証は自動テストでカバーし、GitHub Actions で実行する |
| NFR-09 | 拡張性 | コンテンツの追加は JSON の追記と音声生成スクリプトの実行だけで済む |

## 6. 画面構成（案）

`stock-daytrade` と同じくタブで切り替える。v0.4 で、iPhone の画面幅に収まるよう「ディクテーション」タブの表示名を「書き取り」にした（機能は FR-10 のまま）。v0.5 で「シャドーイング」タブを追加した。

| タブ | 内容 |
|------|------|
| 🏠 今日 | 今日の復習件数、連続学習日数、「続きから」「5分クイズ」「書き取り」「聞き流し」のショートカット |
| 📝 クイズ | 時間と領域を選んで開始 → 1 問ずつ回答 → 結果 |
| ✍️ 書き取り | 音声を聞く → タイプ → 答え合わせ（単語ごとの色分け）→ 次へ |
| 🎧 聞き流し | 単元またはおまかせのプレイリストを選んで再生（英語のみ） |
| 🗣 発音 | 英文・意味・解説を見ながらお手本を聞く → 読み上げ → 判定（Should） |
| 🔁 シャドーイング | 英語の音声だけを聞く → 聞こえたとおりに言う → 判定と英文の表示（Should） |
| 📚 辞書 | 収録項目の検索・閲覧（音声再生付き） |
| 📊 記録 | 領域別の正答率・苦手項目（Should） |

## 7. 制約・リスク

| No | 内容 | 影響 | 対策案 |
|----|------|------|--------|
| R-01 | Streamlit Community Cloud はしばらく使わないとスリープし、起動に数十秒かかることがある | 朝一番の起動が遅い | 外部の定期アクセスで起こしておく、または待ち時間に許容できるか実際に確認する |
| R-03 | Streamlit Cloud のファイル領域は再起動で消える | 学習履歴をサーバー上のファイルには置けない | 非公開の GitHub Gist に保存する（Q-01） |
| R-03b | Gist への保存は 1 回あたり 1 秒前後かかり、API の回数制限もある | 1 問ごとに保存すると操作が重くなる | 数問ごと・セッション終了時・タブ切替時にまとめて保存する（FR-05 の「最大数問分の損失」の範囲内） |
| R-04 | 画面ロック中も再生が続くかは、OS・ブラウザ・Streamlit の音声部品の組み合わせで変わる | 聞き流しモードが使えない恐れ | 第 1 段階で iPhone の実機（Safari と、ホーム画面に追加した場合の両方）で検証し、だめなら再生方式を変える。v0.4 の端末読み上げ方式では画面ロックで止まるため、画面を消さないスイッチで代用中 |
| R-05 | 公開リポジトリのため、コンテンツと音声は誰でも見られる | 音声合成サービスの利用規約上、公開してよいか確認が必要 | 音声合成の方式を決める際に利用規約を確認する |
| R-06 | AI が作成したコンテンツには誤りが混じる可能性がある | 誤った表現を覚える | 例文はビジネスで定番の表現に限定し、利用者が誤りを見つけたら報告・修正できる仕組み（項目ごとの「要確認」フラグ）を設ける |
| R-07 | iPhone の Safari 標準の音声認識は、Streamlit コンポーネントの iframe 内でマイク許可が通らない、ホーム画面に追加した状態では動かない、iPhone の音声入力（Siri・音声入力）の設定に左右される、といった可能性がある | 発音・シャドーイングの判定が使えない | 第 1 段階で iPhone の実機で確認する。使えない場合の無料の代替案は (a) 聞き比べの自己評価のみ、(b) 無料のオープンソース音声認識（小型モデル）を Streamlit Cloud 上で動かす。(b) は依存が増え、無料枠のメモリで動くかの検証が必要 |
| R-08 | ブラウザの音声認識は、音声を各ブラウザ提供元のサーバーに送って処理する場合がある | 読み上げた例文が外部に送られる | 読み上げるのは例文のみで個人情報は含まれない旨を README に記載する |
| R-09 | iPhone の Safari は、利用者のタップなしでの音声の自動再生を制限している | ディクテーションやクイズで、次の問題の音声が自動で流れない | 問題ごとに「再生」ボタンを押す前提で画面を作る。聞き流しは 1 本に結合した MP3 にして、最初の 1 回のタップで最後まで流れるようにする（v0.4 では、最初のタップで始めた読み上げを次の文へ続けて流す方式で代用） |
| R-10 | iPhone の自動修正・自動大文字化で、タイプした英語が書き換わる | 聞き取れていたのに不正解になる | 大文字小文字の違いは無視し、1 文字違いは「惜しい」と判定する（FR-10）。v0.4 では入力欄に自動修正・自動大文字化・スペルチェックを止める属性を付けた。実機で効くかは未確認 |

## 10. 受け入れ基準（初期版）

- iPhone の Safari で公開 URL を開き、2 タップ以内でクイズを始められる
- 5 分のクイズを完走すると、結果が学習履歴に保存される
- ディクテーションで英文をタイプして答え合わせすると、単語ごとの正誤が色分けで表示され、大文字小文字・句読点・縮約形の違いは不正解にならない
- アプリを閉じて開き直すと、前回の続きと今日の復習件数が表示される
- 正解した問題は翌日以降に、間違えた問題は同じ日か翌日に再び出題される
- `pytest` がローカルと GitHub Actions の両方で成功する
- リポジトリに API キーやトークンが含まれていない
